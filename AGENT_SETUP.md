## Что это за бот (объясни владельцу простыми словами)

Личный помощник-задачник в Telegram. Владелец **голосом или текстом** ставит задачу —
бот её понимает, и дальше:
- если назван исполнитель — **передаёт задачу ему** в личку и контролирует выполнение;
- если исполнитель не назван — это **задача себе**, бот напомнит вовремя;
- **напоминает** о задачах (себе — за 2 часа / 1 час / 15 минут до срока);
- собирает **статус** от исполнителя («делаю / готово / застрял») и пересылает владельцу;
- если задача просрочена — **предупреждает** владельца;
- каждое утро присылает **сводку задач на день**.

Работает 24/7 на Railway, даже когда компьютер владельца выключен.

## Где хранятся данные (важно — внешняя БД НЕ нужна)

Все данные — задачи, статусы, **список исполнителей с их Telegram-аккаунтами**, расписание
напоминаний — лежат в **одном файле базы SQLite** (`data/bot.db`) прямо внутри проекта.
**Supabase, Postgres и любые внешние базы НЕ нужны.**

Единственное, что требуется на Railway, — подключить **volume** (постоянный диск) на путь
`/data`, чтобы этот файл не стирался при перезапусках. Это одна настройка (шаг 9), а не
отдельный сервис с регистрацией.

## Главные правила для тебя (ИИ)

1. **Веди по одному шагу.** После каждого шага проверяй результат, прежде чем идти дальше.
2. **Делай сам всё, что можешь** (создавай и правь файлы, запускай команды, заполняй `.env`).
   Владельцу оставляй только физически ручное: вставить токен из Telegram, нажать кнопки
   в браузере, привязать карту.
3. **Объясняй простым языком**, без жаргона. Шаг не получился — покажи точную причину и
   почини сам, не перекладывай на владельца.
4. **НИКАКОГО Google Calendar / OAuth в основном пути.** Бот полностью работает без него.
   Подключай Google Calendar ТОЛЬКО если владелец прямо попросит (раздел 9 в `ONBOARDING.md`),
   и предупреди, что это заметно сложнее.
5. **Секреты — только в `.env`** (он в `.gitignore`). Никогда не коммить `.env`, токены,
   ключи. Репозиторий держать **private**.

## Пошаговый план

### Шаг 1. Окружение
Проверь: `python --version` (нужен 3.11 или новее) и `git --version`. Если чего-то нет —
помоги поставить под ОС владельца (Windows: с python.org, на первом экране галочка
«Add Python to PATH»; git — с git-scm.com).

### Шаг 2. Зависимости и самопроверка
В папке проекта:
- создай виртуальное окружение: `python -m venv .venv`
- активируй его: Windows PowerShell — `.venv\Scripts\Activate.ps1` (если PowerShell ругается
  на политику — `Set-ExecutionPolicy -Scope Process Bypass` и повтори); Windows cmd —
  `.venv\Scripts\activate.bat`; macOS/Linux — `source .venv/bin/activate`
- поставь зависимости: `pip install -e ".[dev]"`
- прогони тесты: `pytest -q` — всё должно быть зелёным. Это проверка, что код цел;
  если что-то красное — разберись и почини до продолжения.

### Шаг 3. Создать Telegram-бота
Попроси владельца: открыть **@BotFather** → `/newbot` → задать имя и username (должен
заканчиваться на `bot`) → BotFather пришлёт **токен** (длинная строка с двоеточием).
Попроси прислать токен тебе в чат.

### Шаг 4. OpenAI ключ
Попроси владельца: на `platform.openai.com` → Billing → привязать карту и пополнить ~$5 →
API keys → Create new secret key → прислать ключ (`sk-...`). Предупреди: ключ показывается
один раз, никому больше его не показывать.

### Шаг 5. Telegram ID владельца
Попроси владельца написать боту **@userinfobot** команду `/start` — тот пришлёт число
(его ID). Это значение пойдёт в `VITALY_USER_ID`.

### Шаг 6. Заполни `.env` (делаешь сам)
Сначала проверь: если файл `.env` **уже существует** — НЕ перезаписывай его вслепую (в нём могут
лежать чужие рабочие ключи). Покажи владельцу содержимое и спроси, прежде чем менять. Эталон
набора переменных — только `.env.example`; ничего из посторонних старых `.env` не переноси.

Скопируй `.env.example` → `.env` и впиши:
- `TELEGRAM_BOT_TOKEN` — из шага 3
- `OPENAI_API_KEY` — из шага 4
- `VITALY_USER_ID` — из шага 5
- `DB_PATH=./data/bot.db`
- `TZ=Europe/Kyiv`
- `MORNING_DIGEST_HOUR=8` (час утренней сводки)

`ASSISTANT_USER_ID` оставь пустым — исполнителей добавим прямо в боте.
Все `GOOGLE_*` оставь пустыми — Google Calendar не используем.

### Шаг 7. Запуск и проверка локально
Запусти `python -m app.main`. В логах (сверяй по подстроке, не дословно) должны появиться:
`Scheduler started`, `Google Calendar DISABLED (prototype mode)`, `healthcheck on :8080/health`,
и в конце — `bot started`. Главное — увидеть `bot started`.
Попроси владельца написать боту `/start`, затем надиктовать голосом, например:
«напомни мне через 2 минуты — тестовая задача». Убедись, что бот распарсил задачу,
показал карточку с кнопкой ✅, и через 2 минуты пришло напоминание.

> ⚠️ Пока бот запущен локально (этот терминал) — не запускай его одновременно на Railway
> с тем же токеном: Telegram разрешает только одно подключение на бота, иначе будет ошибка
> «Conflict: terminated by other getUpdates». Для финальной работы оставляем только Railway.

### Шаг 8. Исполнители (если нужно делегировать)
Для каждого исполнителя:
1. он открывает того же бота и жмёт `/start` → бот пришлёт ему его **ID**;
2. он передаёт ID владельцу;
3. владелец пишет боту `/add_executor <id> <имя>` (например `/add_executor 123456789 Оля`);
4. проверка — команда `/executors`.

Тест: владелец говорит «сделай афишу к пятнице, ответственный — Оля» → задача уходит Оле
в личку. Важно: исполнитель должен хоть раз нажать `/start`, иначе Telegram запрещает боту
писать ему первым.

### Шаг 9. Деплой на Railway (работа 24/7)

> Весь базовый деплой делается через **веб-интерфейс Railway** и `git push`.
> Railway CLI и Node.js НЕ нужны (они всплывают только в опциональном Google-разделе ONBOARDING).

1. Залей проект на **GitHub владельца**, репозиторий **private**. Проверь, что `.env`
   НЕ попал в репозиторий (там должен быть только `.env.example`).
2. Railway → New Project → Deploy from GitHub repo → выбери репозиторий.
3. **Variables** — задай явно (а не «как в .env»):
   - **Обязательные** (без любой бот не стартует): `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`,
     `VITALY_USER_ID` (число, без пробелов и кавычек), `DB_PATH=/data/bot.db` (один слеш — путь на volume).
   - **Опциональные** (есть дефолты): `TZ=Europe/Kyiv`, `MORNING_DIGEST_HOUR=8`.
     `ASSISTANT_USER_ID` и `GOOGLE_*` — не задавать.
4. **Settings → Volumes** → New Volume, mount path `/data`. Без volume база стирается при
   каждом передеплое — обязательный шаг.
5. **Settings → Networking → Generate Domain** — получи публичный адрес `*.up.railway.app`
   (без него не будет URL для проверки в браузере).
6. **Settings → Healthcheck Path**: `/health`. (Порт код берёт из `$PORT` Railway автоматически.)
7. Проверь: открой `https://<твой-сервис>.up.railway.app/health` → должно быть `ok`; напиши
   боту в Telegram — отвечает. Если не так — Deployments → Logs, ищи строку `bot started`.

### Шаг 10. Передача владельцу
Объясни: чтобы что-то поменять («добавь напоминание за день», «поменяй текст»), он просто
просит тебя (ИИ) в этом проекте — ты правишь код, делаешь `git push`, Railway передеплоит
за минуту автоматически.

## Как пользоваться ботом (памятка владельцу)

Ставить задачи — голосом или текстом, естественной речью:
- себе: «напомни мне завтра в 17:00 оплатить аренду»;
- исполнителю: «Оля, сделай афишу к пятнице 18:00, напомни ей сегодня в 20:00»;
- бот покажет карточку — подтверди кнопкой ✅.

Команды владельца:
- `/tasks` — список активных задач;
- `/executors` — список исполнителей;
- `/add_executor <id> <имя>` — добавить исполнителя;
- `/cancel <id>` — отменить задачу.

Исполнитель отвечает боту в личку по своей задаче: «делаю», «готово», «застрял» — статус
автоматически уходит владельцу; «готово» закрывает задачу.

## Если что-то ломается
- **Бот молчит:** запущен? владелец писал именно ему? нажал `/start`? `VITALY_USER_ID` верный
  (сверь через @userinfobot)?
- **Исполнитель не получает задачи:** он нажимал `/start` у бота? добавлен через `/add_executor`?
- **Напоминания не приходят:** бот работает 24/7 (на Railway, а не на выключенном ноутбуке)?
  `TZ` правильная?
- **Ошибка «Conflict … getUpdates»:** бот запущен в двух местах сразу (локально и на Railway).
  Оставь только одно.
- **На Railway падает после старта:** чаще всего забыта переменная окружения — сверь Variables
  со списком из шага 9.3. И проверь, что `DB_PATH=/data/bot.db` и volume на `/data` подключён.
- **Бот стартовал, но на голосовую/текстовую задачу отвечает ошибкой:** обычно на OpenAI нулевой
  баланс или не привязана карта — пополни на platform.openai.com. Сам запуск от этого не падает,
  ошибка вылезает именно при обработке задачи.
- **При локальном запуске ошибка про адрес/порт 8080:** порт занят другой программой — закрой её
  или задай другой порт переменной окружения `PORT`.

инструкция, если всё же нужно, — в `ONBOARDING.md`, раздел 9.
